The first part of the 7.4 merge window

For humans, by humans

Every article on LWN.net is written for humans, by humans. If you've enjoyed this article and want to see more like it, your subscription goes a long way to keeping the slop at bay. We are offering a free one-month trial subscription (no credit card required) to get you started.

By Daroc Alden
October 23, 2026

Since the merge window for 7.4 opened, there have been 6,753 non-merge changesets pulled into the mainline repository. Many more are expected, especially given the possibility that this merge window will be extended to three weeks. Still, even this initial set brought in a number of new features, in addition to the continued general cleanups and security fixes that the kernel has seen recently.

The most important changes included in this release were:

Architecture-specific

  • Alpha now supports a number of different optional architecture features, such as gcov instrumentation and an additional page-table bit. These changes should make Alpha considerably more consistent with other architectures and more performant, although there is still no new Alpha hardware being produced. There has also been a fix for software floating-point emulation, which should make Alpha floating-point code more consistent across different hardware configurations.
  • Arm no longer supports supersection mappings, which are a way to group multiple PMD-level huge pages into one unit. When they were enabled, they took several bits in hardware addresses, which could lead to problems for platforms with only 36 bits for physical memory addresses. Since there are no known users, removing it was judged simpler than trying to free additional bits in the address representation.
  • User-mode Linux can now be used to test NOMMU configurations. User-mode Linux is a useful way to run kernel code in an ordinary process, typically for testing, but it has only been useful for testing kernel configurations that make use of an emulated memory-management unit (MMU). Now, the parts of the kernel that required that have been made optional, so user-mode Linux can be used to test embedded configurations that lack a MMU.

Core kernel

  • A new CLOSE_RANGE_EXCEPT flag allows close_range() to close all file descriptors outside a chosen window, which should make it easier to control which file descriptors are shared with a child process. The CLOSE_RANGE_CLOEXEC_ONLY flag can be used to restrict closures in a range to operate only on close-on-exec file descriptors. Closing a range of files is also now synchronous, which reduces the number of atomic operations needed to empty the file descriptor table when a process exits, and makes the code for handling kernel threads less complicated.
  • Kernel configurations now support additional shortcuts for defining string, integer, and hexadecimal settings. Corresponding shortcuts for defining boolean and tristate settings have existed for some time, so this addition makes the config language a little more consistent.
  • Using sysfs to bind and unbind devices from a driver now marks the kernel as tainted, since this was originally intended as a debugging interface. The change was motivated by a number of fuzzing reports about kernel problems caused by binding devices to the wrong drivers. Only root is able to do that, but users still probably shouldn't rely on the ability.
  • Sched_ext schedulers can now preempt running CPUs lazily, part of the long-running work to enable lazy preemption. Sched_ext schedulers can also now support handling proxy execution thanks to a new set of hooks. That patch set attracted some discussion before it was merged. Work on making nested sub-schedulers more feature-complete is also continuing.
  • Core dumps sent over sockets now made have continuous ranges of zeros compressed, drastically cutting down on the number of bytes that must be sent, and slightly changing the socket format. Core-dump servers can also use new options to get more information about the specific thread responding to a request for a core dump.

Filesystems and block I/O

  • Support for BFS, the filesystem that UnixWare devices use for their boot partitions, has been removed. The filesystem is not believed to have any users, and there is no particular reason to access these boot partitions from Linux, so hopefully it will not be missed.
  • The iomap subsystem now uses lazy bounce buffering for reads with a hardware checksum, such as those used by XFS. Bounce buffering (allocating a separate buffer in the kernel and copying data from user space into it before sending it to the storage hardware) is needed to protect against concurrent modification by user space. For hardware that supports checksumming blocks as they are written, the kernel can now detect concurrent modification afterward. For the common case, where user-space doesn't tamper with the buffer as it is written, this lets the kernel safely skip allocating the bounce buffer and copying the data into it. If a modification is detected, the code falls back to using a bounce buffer as usual.
  • The Btrfs filesystem has a new set of backup root options that can specify which backup root slot to use. These should not normally be needed, but could make recovering from filesystem corruption slightly less of a headache.
  • EROFS filesystems that are mounted multiple times from the same backing file now share a superblock, resulting in lower memory usage.

Hardware support

  • Clock: Renesas RZ/N1 timers.
  • GPIO and pin control: ROHM BD73800 PMIC GPIO controllers, Axiado AX3005 SGPIO controllers, Analog Devices AD7768 GPIO controllers, R-Car X5H (R8A78000) controllers, and Tegra 268 GPIO controllers.
  • Industrial I/O: Nuvoton MA35D1 microprocessors, Qualcomm QPIC SNAND v2 controllers, Renesas R-Car Gen5 devices, Realtek RTD1625 SoCs, Synaptics SL2610 I2C controllers, UltraRISC DP1000 I2C controllers, and Novatek NT72676 I2C controllers.
  • Interrupt chips: Annapurna Labs FICs and Qualcomm Purwa SoC interrupt chips.
  • Miscellaneous: MediaTek MT8167 and MT8127 watchdogs, T8140 watchdogs, Exynos 5515 watchdogs, Qualcomm SDM670 and IPQ9650 APCS mailboxes, Apple M4 and A18 Pro processors, Google Laguna Tensor G5 processors, Qualcomm SM8950, SM8975, Glymur, Shikra, and IPQ5424 processors, Exynos5515 mobile processors, Tegra264 SoCs, Tegra410 SoCs, R8A774A3 SoCs, and MT8167 SoCs.
  • Networking: SVEthLANa Ethernet interfaces for Atari SuperVidel FPGA expansion cards, Meta Platforms NICs, X-Powers AC200/AC300 Fast Ethernet PHYs, Qualcomm IPQ5424 Ethernet NICs, RK4568 SGMII NICs, Alwinner H616 EMAC1 NICs, UltraRISC DP1000 NICs, Qualcomm sa8255p NICs, Microchip KSZ8995XA/KS8995XA Ethernet switches, Realtek RTL8261CE_CG and RTL8261D_VM Ethernet PHYs, Realtek RTL8723BS WiFi chips, Mediatek MT7928 Bluetooth chips, Qualcomm QCC2072 Bluetooth chips, and Synaptics 4384 Bluetooth chips.
  • Power management: IPQ9650 CPU frequency controllers, Foxconn WCN7850 power sequencing sensors, Maxim MAX20024 SMPS converters, MPS MPQ4210 buck-boost controllers, Nexperia NEX10000UB dual-output LCD bias power supplies, MP8864 synchronous step-down converters, Qualcomm SM7250, Kuno, and MSM8952 power domains, and Renesas r8a774a3 SYSC power domains.
  • Storage: Altera Agilex5 SD6HC cards, Cadence SD6HC cards, MSM8952 SD cards, and Allwinner B288 SD cards.
  • Thermal: Google GS101 sensors, Renesas RZ/G3L sensors, Qualcomm MSM8952 TSENS sensors, and Qualcomm PMAU0102 Master BandGap temperature monitors.

Miscellaneous

  • binfmt_misc no longer accepts arbitrary delimiters; users will have to stick to punctuation. This is another case of a feature that is not believed to have any users, but that was turning up a disproportionate number of bug reports.
  • A new OPEN_TREE_DROP_MNTNS_MOUNTS flag has been added to open_tree() to work around problems with opening new mount namespaces inside containers. Mount namespaces are not allowed to form a loop; this is enforced by ensuring that older mount namespaces cannot be mounted below newer ones. When creating a container with a new mount namespace, this leads to problems with trying to expose a host directory that already contains a mount from a mount namespace. The new flag drops those mounts from the view of the mounted tree, avoiding the loop.

Networking

  • The TCP ROCCET congestion-control algorithm is now supported. ROCCET is based on CUBIC, but has improved performance when running over a cellular network. Specifically, it should cause less bufferbloat than CUBIC does.

Security-related

  • Detection of page mappings that were both writable and executable in the kernel was broken on x86, and has now been fixed.
  • Eric Biggers has moved many of the architecture-specific AES implementations into the common crypto library, making the library faster and reducing algorithm duplication. SipHash was also moved.
  • There are new security-module hooks for dealing with namespaces.
  • Landlock can now use those hooks to restrict capabilities and namespaces.
  • Keyrings no longer leak kernel addresses, which means they can no longer be used to defeat kernel address-space layout randomization (KASLR). Since the leak was only visible to local users, the patch was not considered a huge problem, but it's still nice to have fixed.

Virtualization and containers

  • A new performance governor for virtual machines that takes into account time stolen by other guests has been added.

Internal kernel changes

  • Christian Brauner fixed a number of bugs surrounding the interaction of core dumps and signals by building a TLA+ model of the relevant parts of the kernel.
  • LLMs are now pointed at the documentation more aggressively. Perhaps now they will reliably read it.
  • Rust code can use new configfs bindings.
  • Linus Torvalds has completely removed __{get,put}_user() in favor of more modern interfaces. This article gives more detail on the scope and nature of the change.
  • It is now possible to call call_srcu() from any kernel context.
  • Support for safe self-referential structures in pin_init has been merged.
  • New kmalloc_obj*()-style type-based allocation APIs for devm_kmalloc() provide safer allocations.
  • A set of seq_buf helpers that was subject to much discussion has been merged as part of a larger cleanup of seq_buf and related code.

There are still 11,461 non-merge changesets waiting in linux-next, almost all of which can be expected to appear in a pull request before this merge window closes. Expect additional updates on changes for the 7.4 kernel to follow.
