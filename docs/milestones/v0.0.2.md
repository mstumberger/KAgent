# Milestone v0.0.2

What was planned (in the stage list, the specs or the planning sessions) and is not
done yet, as of 2026-11-27. Branch: `v0.0.2`. Sources: section F of
`docs/IMPLEMENTATION.md` (stages), the "Open" and "Seen, not changed" notes of
section E, and the planning sessions. Each item names where its detail lives.

## 0. Scope and decisions (owner, 2026-11-27)

In v0.0.2: phase 6 (S41 to S43), the owner's voice todos, the known defects and small
follow-ups, and the open decisions. Phase 5 (coding agents, S35 to S39) moves to v0.0.3.
Terms: `GLOSSARY.md` (Owner, Brain, Watcher, Screen watch, Recommended model).

Order of work, one background agent at a time, each item committed on `v0.0.2` once its
tests pass (no push, no merge):

1. Small defects and the open decisions of section 3 (all ten as recommended; phase 5's
   questions wait for v0.0.3).
2. Voice (S44, `specs/voice-control.md`): a `settings` tool (reads every setting; changes all except permission mode,
   hooks, tool overrides, provider keys and the Telegram token; every change confirmed
   out loud); speaking voice and volume by voice; `terminal send` asks when it comes
   from voice (chat in `full` stays silent); the first greeting asks the owner's name
   when `persona.address` is empty (delete task `t56cca8ba`); `live` is the default
   voice mode, with a note in Settings when `routed` runs on a slow Brain; the agent
   reads "Brain" as the chat model.
3. [x] Google Calendar (S45, `specs/calendar.md`; built 2026-11-27 night, section E of
   `IMPLEMENTATION.md`; the owner checks it against a real account, scenario S45 item 9),
   a native module (not an MCP plugin) with its own Settings page
   "Calendar":
   - [x] Sign-in with Google (OAuth for a desktop app, the owner's own Google Cloud
     client; the refresh token in the desktop keyring). The page lists the account's
     calendars with a switch each (primary on); the agent and the report see only
     those.
   - [x] A `calendar` tool group: read, add, change and delete events; every change is
     confirmed out loud first, a delete needs "confirm".
   - [x] Adding an event is an interview: title, day and time, duration (default 1 h),
     location, calendar (default primary), reminder (default Google's), notes, and a
     Google Meet link when asked; guests only when the owner mentions them. The
     event is read back and saved after a spoken OK.
   - [x] Location: with a Google Maps API key on the page, the Places API finds the place
     (name, address, Maps link); without one, a web search and a Maps search link.
     The interview reads the place back.
   - [x] Morning report: weekdays at 07:45, weekends at 09:00 (changeable). It holds today's
     events with time and place and overlaps flagged, the leave-by time for the first
     event with a place (by car from the home address on the page, traffic plus 10
     minutes; needs the Maps key), tomorrow's first event, and KAgent's own tasks and
     reminders for the day. Channels, each a switch on the page: spoken at the first
     voice talk after the report time, and Telegram at the report time.
   - [x] Owner actions: create the Google Cloud OAuth client and enable the Calendar API;
     for maps, an API key with Places and Routes.
4. S41 model picker in the composer.

8. (done) Recommended models (S47, `specs/local-models.md`): a separate Settings page "Local models" with the graphics card

9. Screen watch (S48, `specs/screen-watch.md`): on request, with a goal and a time limit ("tell me when the build

10. A professional repository, last so the screenshots show the new interface:
    - GitHub "About": a one-line description, topics (rust, linux, ai-agent, voice-assistant,
      kde, gemini, ollama, sysadmin), no website unless one exists.
    - `README.md` rewritten for a visitor: what KAgent is in two sentences, a screenshot

    - Repository hygiene: a `LICENSE` (GPL-3.0, the owner's choice; the `license` field of every Cargo.toml and package.json to match), `CONTRIBUTING.md` kept short,
      issue and PR templates, and a CI badge once a CI workflow exists.

## 7. From the voice transcript of 2026-11-27

Fixed on this branch:

- [x] Parallel tool calls from Gemini's OpenAI-compatible stream (all under `index`
      0, each with its own `id`) were glued into one call with invalid arguments
      (`{"_raw": "{..}{..}"}`), so the call failed and the agent apologised twice. A
      new `id` on an index now starts a new call (`adapters/openai_chat.rs`).
- [x] `todo_write` replaces the list and the model sent only the new item each time,
      so every earlier item was lost. New `mode: "add"` appends; a replace that drops
      open items names them in the result.
- [x] Voice brain set back to `live` (Gemini Live thinks itself, as before S26). The
      default `routed` sends every utterance to the chat model as a text turn, which
      is slower and, with a non-voice chat model, less fluent.

- [x] In a `live` voice session the model rebooted the PC after "How can we fix it?";
      the card was allowed by a click. Now a call that needs approval is asked out
      loud first, raises no card, and runs only after the owner's spoken answer
      ("confirm" for root and destructive actions); its card is then answered by
      voice (`voice.md` section 12).

- [x] 22:03: the live model typed into the owner's only terminal 25 times in 15 s
      (`full` mode, no question). From voice every `always_ask` call is now asked out
      loud in every mode, and a repeated changing call within 20 s is refused
      (`voice.md`, amendment).

Open:

      question (`always_ask` is let through by `full`, as documented). On 2026-11-27 the
